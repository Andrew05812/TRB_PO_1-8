# SecureAuthApp — защищённая форма авторизации (Практика 4)

Своя реализация формы входа вместо уязвимого примера из DVWA. Формат запроса
намеренно сохранён как в задании:

```
GET /login.php?username=USER&password=PASS&user_token=TOKEN&Login=Login
```

Из-за этого пароль остаётся в URL — это единственный сознательный компромисс,
подробнее в отчёте (`../Отчет_Практика4.docx`, раздел 7).

## Как запустить

Нужен PHP 8.1+ с расширениями pdo_sqlite и mbstring. Если PHP на хост не
установлен, проще всего запустить в контейнере:

```powershell
docker run --rm -d --name secureauth-lab -p 127.0.0.1:8080:8080 -v "${PWD}:/app" -w /app php:8.3-cli php -S 0.0.0.0:8080 -t public
```

(В Git Bash вместо `${PWD}` подставляется `$(pwd)`.)

Дальше открыть `http://127.0.0.1:8080/register.php`, создать пользователя и
войти через `http://127.0.0.1:8080/login.php`. База `data/app.db` создаётся
сама при первом запросе.

Для проверки удобнее создать тестового пользователя из командной строки,
не заходя в браузер:

```bash
docker exec secureauth-lab php tools/seed_user.php testuser "Summer2024!" --reset
```

`--reset` очищает журнал попыток входа. Это допустимо только на учебном
стенде: на реальной системе журнал стирать нельзя.

## Что сделано против перебора

- пароль хранится через `password_hash()` (bcrypt, cost 10), а не `md5()`;
- после 5 неудачных попыток за 15 минут блокируются и логин, и IP;
- при блокировке отдаётся `429` с заголовком `Retry-After`;
- каждая попытка входа задерживается на 1 секунду;
- для несуществующего логина всё равно считается bcrypt от хэша-заглушки,
  поэтому по времени нельзя понять, есть такой пользователь или нет;
- пароль длиннее 72 байт отклоняется — bcrypt всё равно обрезал бы его.

## Остальные меры

- PDO с подготовленными выражениями, эмуляция prepare выключена;
- CSRF-токен `user_token` (32 случайных байта, `hash_equals`) во всех формах;
- `session_regenerate_id(true)` после успешного входа;
- cookie `HttpOnly`, `SameSite=Lax`, `Secure` под HTTPS;
- `X-Frame-Options: DENY`, CSP, `nosniff`, `no-store`;
- ошибки не показываются в браузер, только пишутся в лог;
- регистрация и выход — POST; выход без токена возвращает 403, GET — 405.

## Структура

- `public/` — страницы: index, register, login, dashboard, logout;
- `src/config.php` — лимиты попыток, окно блокировки, длина пароля;
- `src/bootstrap.php` — сессия, заголовки, общий обработчик ошибок;
- `src/db.php` — подключение к SQLite через PDO;
- `src/csrf.php` — сессия и CSRF-токен;
- `src/rate_limit.php` — журнал попыток и расчёт блокировки;
- `schema.sql` — таблицы `users` и `login_attempts`;
- `tools/seed_user.php` — создание тестового пользователя.

## Проверка переборщиком

В соседней папке лежит `bruteforce_dvwa.py`. Против этой формы он запускается
так:

```bash
python bruteforce_dvwa.py --url http://127.0.0.1:8080/login.php \
    --username testuser --wordlist wordlist_p4.txt --results secure_results.csv
```

Ожидаемый результат — 6 попыток и статус `locked_out`: правильный пароль
(`Summer2024!`) стоит в словаре двадцатым, но до него дело не доходит.
